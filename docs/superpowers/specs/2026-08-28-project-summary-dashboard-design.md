# 프로젝트 요약(대시보드) 화면 설계

- **작성일**: 2026-08-28
- **대상**: `alm-front` `/projects/:projectId/dashboard` (뷰 탭 "요약")
- **레퍼런스**: 지라 프로젝트 Summary 뷰(상태 분포·담당자 작업량·최근 활동·마감 임박)
- **관련**: `../../roadmap/2026-08-28-jira-parity-requirements.md` §5.6 리포트, §10-5 리포트 화면 위치

## 1. 목적과 판단 기준

프로젝트에 들어온 사람이 **"지금 이 프로젝트가 어떤 상태인가"를 스크롤 없이 5초 안에** 읽게 한다.
현재 화면은 상태 카운트 타일 4개와 담당자 분포뿐이라, 지연된 일이 있는지·이번 스프린트가 어디까지
왔는지를 답하지 못한다.

Nielsen #1(상태 가시성)과 #8(미니멀)을 기준으로 삼는다. 카드마다 "이 카드를 보고 무엇을 할 수
있는가"를 정의했고, 답이 없으면 넣지 않았다.

## 2. 페이지 구성 (정보 구조)

프로젝트 뷰 탭은 그대로 둔다: 요약 · 타임라인 · 보드 · 백로그 · 이슈 · 설정. 지라와 같은 순서이며
"요약"이 첫 탭이다. 요약 페이지 안쪽만 다시 짠다.

```
┌──────────────────────────────────────────────────────────────┐
│ 지표 타일 4  (전체 · 할 일 · 진행 중 · 완료)                  │  ← 기존 유지
├───────────────────────────────┬──────────────────────────────┤
│ 활성 스프린트                  │ 완료 진행                    │
│ 목표 · 기간 · 남은 일수        │ 완료율 미터 + 지연/마감 임박  │
│ 담은 이슈·완료·예상 시간       │ 건수                         │
├───────────────────────────────┼──────────────────────────────┤
│ 상태별 분포 (커스텀 상태 포함) │ 담당자별 작업량              │
├───────────────────────────────┼──────────────────────────────┤
│ 마감 임박·지연 (최대 5)        │ 최근 업데이트 (최대 5)       │
└───────────────────────────────┴──────────────────────────────┘
```

- 2열 그리드. 두 열(360px + 간격)이 들어가는 폭부터 2열이고 그 아래는 1열이다(약 740px 경계).
  트랙은 `minmax(min(360px, 100%), 1fr)`이라 360px보다 좁은 컨테이너에서도 가로 스크롤이 생기지 않는다.
  지표 타일은 기존처럼 4→2→1 자동 접힘.
- 카드 순서는 "지금 진행 중 → 위험 → 분포 → 흐름" 순. 위험(지연)이 접힘 아래로 밀리지 않게
  첫 화면 안에 둔다.

## 3. 카드별 명세

| 카드 | 데이터 출처 | 형태 | 이 카드로 하는 일 |
|---|---|---|---|
| 지표 타일 4 | `listIssues` + `statusCategory` | 숫자 + 비율 | 규모 파악 |
| 활성 스프린트 | `listSprints`(state=active) + 해당 이슈 | 목표 텍스트 + 기간·남은 일수 + 완료/전체 + 예상 시간 합 | 이번 스프린트가 어디까지 왔나 |
| 완료 진행 | 이슈 카테고리 | 2색 미터(완료/잔여) + 지연·마감 임박 건수 | 끝났나, 위험한가 |
| 상태별 분포 | `listProjectStatuses` + 이슈 | 라벨 붙은 단일 색 가로 막대 | 어느 상태에 쌓였나 |
| 담당자별 작업량 | `listUsers` + 이슈 | 라벨 붙은 단일 색 가로 막대(내림차순) | 누구에게 몰렸나 |
| 마감 임박·지연 | 이슈 `dueDate`, 미완료만 | 목록 + 상태 Lozenge | 오늘 무엇을 먼저 보나 |
| 최근 업데이트 | 이슈 `updatedAt` 내림차순 | 목록 + 상대 시간 | 무엇이 움직였나 |

각 목록 항목은 이슈 키로 상세 모달을 연다(`?issue=` 규약 재사용) — 요약에서 바로 작업으로 간다.

## 4. 시각 규칙 — 색은 계산해서 정했다

`dataviz` 검증기(`validate_palette.js`)로 실제 계산한 결과를 근거로 한다.

- **기각안**: 상태 3분류를 색으로 구분하는 범주형 팔레트(회색/청록/초록).
  라이트 기준 `#0E7490`(진행 중)↔`#707A89`(할 일)의 정상 시야 ΔE 9.3, 프로탄 4.3으로
  **하드 실패**. 다크(`#4CB8CE`↔`#98A2B0`)도 ΔE 8.9로 같은 실패.
- **채택안**: 색으로 범주를 구분하지 않는다.
  - 분포 막대(상태별·담당자별)는 **행마다 텍스트 라벨과 숫자를 직접 붙이고 막대는 브랜드 단일
    색**(`--chanho-color-background-brand`)으로 그린다. 색은 크기 비교만 돕고 신원은 라벨이 진다.
  - 완료 진행 미터만 2색이다: 완료 `--chanho-color-background-success`, 잔여
    `--chanho-color-background-neutral`. 두 색은 대비가 충분하고 퍼센트 텍스트를 함께 쓴다.
  - 상태·우선순위 칩은 기존 `Lozenge` 언어를 그대로 쓴다(색 + 텍스트 병행).
- 지연은 색만으로 표시하지 않는다. `Lozenge appearance="danger"` + "3일 지남" 텍스트를 함께 쓴다.
- 숫자는 `font-variant-numeric: tabular-nums`로 자릿수를 맞춘다(기존 타일 규칙 유지).

## 5. 상태별 정의

- **로딩**: 기존과 동일하게 `Spinner`(label="대시보드 불러오는 중"). 침묵 로딩 금지.
- **빈 프로젝트**: 이슈 0건이면 `EmptyState` 하나만 — "아직 이슈가 없습니다 / 백로그에서 첫 이슈를
  만들면 현황이 여기에 나타납니다".
- **부분 빈 상태**: 활성 스프린트가 없으면 그 카드는 "진행 중인 스프린트가 없습니다 / 백로그에서
  스프린트를 시작하세요". 마감 임박·지연이 0건이면 "마감이 임박한 이슈가 없습니다".
- **에러**: 로드 실패는 빈 목록으로 삼키지 않는다(`platform-frontend` §4). 현재 목업 스토어는
  실패하지 않으므로 이번 범위에서는 로딩·빈 상태만 구현하고, REST 전환 시 에러 상태를 추가한다
  — **레퍼런스 없음, 후속 확인 필요**.

## 6. 접근성

- 막대는 `role="img"`가 아니라 값 텍스트를 함께 렌더한다. 스크린리더는 "이름 / 개수"를 읽는다.
- 진행 미터는 DS `ProgressBar`의 label prop을 채운다(예: "완료 진행률").
- 목록 항목은 `button`이라 키보드로 도달·실행된다. 포커스 인디케이터는 DS 기본을 그대로 둔다.
- 색만으로 구분하는 요소 없음(§4).
- 대비: 브랜드 `#1B66C9`(라이트)·`#3F84DC`(다크) 모두 표면 대비 3:1 이상, 본문 텍스트는 기존
  `text-default`/`text-subtle` 조합을 유지한다.

## 7. 다크모드

새 색을 만들지 않고 시맨틱 토큰만 쓴다. 다크에서 카드 입체감은 그림자가 아니라
`--chanho-color-background-surface-raised` + `--chanho-color-border-default` 조합으로 낸다
(기존 `Card` 동작 그대로).

## 8. 디자인시스템 확장

**이번 범위에서는 확장하지 않는다.** 필요한 표현이 전부 기존 컴포넌트(`Card`·`ProgressBar`·
`Lozenge`·`Avatar`·`Badge`·`EmptyState`)와 토큰 마크업으로 가능하다.

번다운·벨로시티처럼 좌표축이 있는 차트는 이 방식으로 감당되지 않는다. 그건 로드맵 §10-2의
결정(디자인시스템에 Chart 추가 vs alm-front 인라인 SVG) 이후에 만든다.

## 9. 레퍼런스 없음 — 임시 적용 목록

- 마감 임박 기준 7일, 목록 상한 5건: 지라 캡처 없이 정한 값이다. 후속 확인 필요.
- 담당자 막대 상한 8명 + "기타 N명" 접기: 시드가 4명이라 실제 검증 못 함. 후속 확인 필요.
- "남은 일수" 계산은 `plannedEnd` 기준 오늘 포함. 기간 미설정 스프린트는 이 줄을 숨긴다.
