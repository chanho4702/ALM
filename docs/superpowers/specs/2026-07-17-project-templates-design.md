# 프로젝트 생성 템플릿 설계 (2026-07-17)

ALM 고도화 5차(분해안 마지막). 프로젝트 생성 시 템플릿을 골라 보드 구성·스프린트·샘플
이슈까지 자동 세팅한다.

## ALM 특색

- **정직한 미리보기**: 템플릿 카드가 실제로 만들어질 컬럼 구성(WIP 포함)과 포함물
  (샘플 이슈 수·스프린트)을 그대로 보여준다 — 지라의 추상적인 템플릿 설명 대비 구체적.
- **빈 프로젝트로 시작** 옵션이 항상 첫 자리에 — 템플릿 강요 없음.
- 샘플 이슈로 **첫 화면이 비어 보이지 않게** 온보딩 (삭제해도 무방한 더미).

## 템플릿 정의 (`store/projectTemplates.ts` — 정적 데이터)

```ts
type ProjectTemplateId = "blank" | "scrum" | "kanban" | "bugtrack";
interface ProjectTemplate {
  id: ProjectTemplateId;
  name: string;          // 빈 프로젝트 / 스크럼 / 칸반 / 버그 트래킹
  description: string;
  glyph: string;         // 카드 아이콘 (◻ ⚡ ▤ ●)
  preview: string[];     // 컬럼 미리보기 ["할 일", "진행 중 (WIP 3)", "완료"]
  includes: string[];    // 포함물 ["Sprint 1", "샘플 이슈 3개"]
}
```

| 템플릿 | 기본 보드 | 추가 세팅 |
|---|---|---|
| 빈 프로젝트 | 스크럼 "메인 보드" (현행 그대로) | 없음 |
| 스크럼 | 스크럼 "스프린트 보드" | `Sprint 1`(planned) 생성 + 백로그 샘플 이슈 3개(스토리/작업/작업) |
| 칸반 | 칸반 "칸반 보드", 진행 중 WIP 3 | 샘플 이슈 3개 (칸반이라 바로 보드에 보임) |
| 버그 트래킹 | 칸반 "버그 보드", 저장 필터 타입=버그 | 샘플 버그 2개(라벨 `bug`) + 일반 작업 1개(보드 밖 확인용) |

## 스토어

- `createProject(input)`에 `templateId?: ProjectTemplateId` 추가 (기본 `"blank"` — 기존 호출
  동작 불변). 생성 직후 템플릿 적용:
  - 기본 보드의 이름/타입/컬럼/필터를 템플릿대로 교체
  - 스크럼 템플릿이면 `Sprint 1`(planned) 생성
  - 샘플 이슈 생성 (reporterId 현재 사용자, created 활동로그 포함 — createIssue 경유)
- `PROJECT_TEMPLATES: ProjectTemplate[]` export (UI 카드 데이터 원천 = 실제 적용 로직과 같은 파일)

## 화면 (`ProjectCreatePage`)

- 이름/키/설명 폼 위에 **템플릿 카드 그리드**(radio 역할): 글리프·이름·설명·컬럼 미리보기
  (`할 일 | 진행 중 (WIP 3) | 완료` 형태)·포함물 뱃지. 선택 카드는 브랜드 테두리.
- 기본 선택: 빈 프로젝트 (강요 없음 원칙).
- 생성 → 템플릿 적용된 프로젝트의 보드로 이동.

## 테스트

- 스토어: 템플릿별 결과(보드 이름/타입/WIP/필터, 스프린트 유무, 샘플 이슈 수), blank는
  기존 스냅샷과 동일, 기존 createProject 호출 무변화
- UI: 템플릿 선택 → 생성 → 보드 툴바에 템플릿 보드 이름, 기존 생성 테스트 유지

## 범위 제외

커스텀 템플릿 저장, 템플릿별 워크플로(상태 3개 유지), 조직 공유 템플릿(백엔드).
