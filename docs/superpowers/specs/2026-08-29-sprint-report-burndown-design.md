# 스프린트 리포트 · 번다운 설계

- **작성일**: 2026-08-29
- **대상**: `alm-front` 프로젝트 요약 하위 리포트 화면, `alm-backend` 집계 API
- **요구사항**: `../../roadmap/2026-08-28-jira-parity-requirements.md` S4·S5
- **레퍼런스**: 지라 [번다운 차트](https://support.atlassian.com/jira-software-cloud/docs/view-and-understand-the-burndown-chart/) · [스프린트 리포트](https://support.atlassian.com/jira-software-cloud/docs/generate-a-report/)

## 1. 무엇을 답하는 화면인가

- **번다운**: "남은 일을 남은 기간에 끝낼 수 있나."
- **스프린트 리포트**: "무엇이 끝났고 무엇이 남았으며 도중에 무엇이 들어왔나."

두 카드는 같은 페이지(`/projects/:id/reports`)에 세로로 쌓고, 상단에서 스프린트를 고른다.
기본 선택은 활성 스프린트이고, 없으면 가장 최근 완료 스프린트다.

## 2. 데이터 원천 — 서버 이력이 정본

`GET /api/alm/projects/{id}/changes`(2026-08-29 구현)가 상태·스프린트 소속 변경을 시간순으로 준다.
번다운은 이 이력만으로 재구성한다. 브라우저 저장소를 근거로 삼지 않는다(요구사항 S6).

목업 모드(`jiraStore`)에서는 같은 역할을 `activities`가 한다 — 계약 시그니처는 동일하게 두고
내부만 갈린다(불변 규칙 1).

**완료 판정은 아직 프론트가 안다.** 서버는 상태 id만 알고 카테고리(todo/inprogress/done)는
워크플로 스킴을 가진 프론트 소유다. 그래서 집계는 프론트에서 하고, 서버 API는 원천 이력을 준다.
스킴이 서버로 넘어가면 집계도 서버로 옮긴다 — 그때 화면은 시리즈 계약만 유지한다.

## 3. 번다운

### 축과 단위

- **가로축**: 스프린트 기간. `plannedStart` ~ `plannedEnd`가 있으면 그 구간, 없으면 실제 시작일 ~
  오늘. **예정 종료일을 넘겨 완료했으면 실제 완료일까지 늘린다**(로드맵 §10-3 결정) — 잘라내면
  마지막 구간의 잔여가 사라져 "끝났는지"를 답하지 못한다.
- **세로축**: 잔여 **예상 시간(h)**이 기본이다(로드맵 §10-1 결정 유지). 스프린트에 예상 미입력
  이슈가 있으면 차트 위에 "예상 미입력 N건 — 이 이슈는 합계에 들어가지 않습니다" 캡션을 띄우고,
  **이슈 수 기준 토글**을 함께 둔다. 미입력이 많은 프로젝트에서 시간 기준 번다운은 거짓말을 한다.

### 선

| 선 | 의미 | 표현 |
|---|---|---|
| 기준선 | 시작 총량에서 종료일 0까지 직선 | 2px 점선, `--chanho-color-text-subtle` |
| 잔여선 | 이력으로 재구성한 일자별 잔여 | 2px 실선, `--chanho-color-background-brand`, 계단형(step) |

두 선뿐이라 범례는 두 항목이고 직접 라벨도 붙인다(`dataviz` 규칙: 2개 이상 시리즈면 범례 필수).
색만으로 구분하지 않게 기준선은 점선, 잔여선은 실선으로 형태도 다르게 한다.

### 라이브러리

**Recharts 3.x(MIT)** 를 쓴다 — 사용자 확정 조건(오픈소스 허용, MIT만)에 맞고 React 19를 지원한다.
Apache ECharts는 Apache-2.0이라 조건에서 제외했다. 색·글꼴·격자선은 전부 `--chanho-*` 토큰을
넘겨 디자인 언어를 맞춘다. Recharts 기본 팔레트를 쓰지 않는다.

## 4. 스프린트 리포트

세 묶음으로 나눈 목록이다. 각 행은 이슈 키·제목·상태·담당자이고 누르면 상세 모달을 연다.

| 묶음 | 정의 |
|---|---|
| 완료 | 완료 시점에 카테고리 done이었던 이슈 |
| 미완료 | done이 아니었던 이슈 + 이관 행선지(다음 스프린트 이름 또는 백로그) |
| 스코프 변경 | 시작 이후 편입된 이슈(추가), 시작 이후 빠진 이슈(제거) |

헤더에는 완료/미완료 건수와 예상 시간 합계를 둔다. 스코프 변경이 0건이면 그 묶음은 렌더하지 않는다.

## 5. 상태별 정의

- 스프린트가 하나도 없으면 페이지 전체가 `EmptyState` — "스프린트를 만들면 리포트가 나타납니다".
- 선택한 스프린트에 이슈가 없으면 차트 대신 "이 스프린트에는 이슈가 없습니다".
- 기간이 없고 시작도 안 한 스프린트(planned)는 번다운을 그리지 않고 "시작하면 번다운이 그려집니다".
- 이력이 비어 있으면(예: 목업 데이터를 방금 시드) 잔여선은 시작 총량에서 평평하다 — 이는 결함이
  아니라 사실이므로 캡션으로 알린다.

## 6. 접근성

- 차트에는 `role="img"` + `aria-label`(예: "Sprint 1 번다운, 잔여 12시간, 3일 남음")을 준다.
- 차트 아래에 같은 데이터를 표로 제공한다(`dataviz` 규칙: 표 뷰 항상 존재). 표는 `details`로 접어둔다.
- 단위 토글은 라디오 그룹이고 키보드로 조작된다.

## 7. 남은 판단

- 시간 기준과 이슈 수 기준 중 **기본값**: 위 §3은 시간 기준을 기본으로 두되 미입력 경고를 띄운다.
  실제 사용 데이터를 보고 이슈 수 기준을 기본으로 바꿀 여지를 남긴다 — **후속 확인 필요**.
- 스프린트 리포트에 벨로시티(과거 스프린트 완료량 추이)를 붙일지는 R2로 미룬다.
